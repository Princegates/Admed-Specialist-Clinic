# ADMed Specialist Clinic — website

Static site (HTML + CSS + JS, no build step). The site lives in `public/`; open `public/index.html` locally.

## Deploying (Cloudflare)
`wrangler.jsonc` serves the `public/` folder as static assets. Build command: none. Deploy command: `npx wrangler deploy`. The `name` in `wrangler.jsonc` must match the Worker/project name in the Cloudflare dashboard.

## Adding the clinic's real details
Edit **`public/assets/js/config.js`** — the only file you need to touch:

- `phone`, `address`, `mapsUrl`, `mapEmbedUrl`, `announcement`, `googleRating` and `reviews` are filled from the clinic's Google Maps listing.
- `whatsapp`, `email`, `hours`, `social` — still empty, so hidden. Add them to show WhatsApp/email booking, opening hours and social icons.
- `photos` — put images in `public/assets/photos/` and list them (`hero`, `about`, `services` tiles, `gallery`). The gallery appears once photos exist.
- `doctors`, `reviews` — the Team and Reviews sections appear once you add entries.

The eleven services (Cardiac, Nephrology, Dialysis, Dialysis Access Procedures, Orthopedic, Gynecological, Hematology, Urology, Internal Medicine, Physician Specialist, Medical Laboratory) are in `public/index.html` under `#specialties`; the booking dropdowns update automatically.

## Automatic deploys (GitHub Actions)
`.github/workflows/deploy.yml` deploys the site to Cloudflare on every push. Add two repository secrets in GitHub (Settings, Secrets and variables, Actions): `CLOUDFLARE_API_TOKEN` (a token from the "Edit Cloudflare Workers" template) and `CLOUDFLARE_ACCOUNT_ID`. You can also run it by hand from the Actions tab.

## Appointment emails and chat
- **Forms to email:** the appointment forms send requests to the clinic's email through Web3Forms (free). Go to web3forms.com, enter the clinic email, then paste the access key they email you into `formAccessKey` in `public/assets/js/config.js`. Until then the form opens the visitor's email app.
- **Chat button:** `chat.routes` in the same file lists what visitors can pick (appointment/clinic, specialist) and which number each goes to. Each opens WhatsApp with their message, or lets them call.

## Service pages
Each service tile on the home page opens its own page (`public/services/<name>.html`), for example `public/services/nephrology.html`. The eleven pages are generated from one template so they always match the home page:

1. Edit the text in `tools/services_content.py` (offers, explanations, when to book, clinic days).
2. Run `python3 tools/build_services.py`.
3. Commit the changed files in `public/services/`.

If you add or rename a service, also update its tile in `public/index.html`.

## Cookie policy
`public/cookies.html` is generated by `tools/build_services.py` (the text and table are in that file). If you add analytics, ads or another third-party service, add it to the table and tell visitors; a consent banner may then be needed.

## Day / night mode
The sun/moon button in the header switches themes. The choice is remembered, and first-time visitors get their device's light/dark setting.

Brand colours (sampled from the logo): navy `#00007E`, amber `#FCA901`, red `#FE0000`.

## News, Updates & Health Insights

The home page section (`#updates`) is fed by the `news` list in `public/assets/js/config.js`. Each entry has a `type`: `clinic` (Clinic Updates), `insight` (Health Insights, opens its own article page `insight.html?id=...` from the entry's `body`) or `local` (Local Health News, a short summary with a link to the source). The comments above `news` in `config.js` explain every field. The section shows three blocks: Health Insights (newest article featured, the next ones listed beside it), Clinic Updates (poster cards) and Local Health News (dated rows with the source). A block is hidden until it has an entry, newest dated entries come first, and each block has a "More" button once it holds more than it shows. Save the file and push: the site redeploys by itself. No build step is needed for news.

## Live health news

`src/worker.js` is a small Cloudflare Worker that serves the site and one extra address, `/api/health-news`. It reads the public health news feeds of the World Health Organization, allAfrica (Health and Medicine) and Graphic Online (Ghana health) on the server, keeps the headlines for 20 minutes and returns only the headline, link, source and time. The page shows them in the scrolling "Health news" ticker under the header (only headlines under 24 hours old, set by `whoTickerHours` in `public/assets/js/config.js`) and in the "Health News" list in the news section. Visitors' browsers never contact the sources, and no keys are needed. Links must point to the source's own website. If the feeds are unavailable the ticker and list stay hidden. Set `whoNews: false` in `config.js` to switch it off. To add a source, add a line to `SOURCES` at the top of `src/worker.js`.

The deploy command is unchanged (`wrangler deploy`); `wrangler.jsonc` names `src/worker.js` as the Worker and `public/` as its assets.

## SEO

Search-engine tags are generated, not hand-written. `python3 tools/build_services.py` writes, for every page: a unique title and description, the canonical link, social-preview (Open Graph and Twitter) tags and structured data (the clinic with its address, hours and services on the home page; breadcrumbs and a medical web page on service pages; an Article on each health guide). It also writes `public/sitemap.xml` and `public/robots.txt`, and builds one real page per Health Insights entry in `public/insights/` from the `news` list in `config.js`. Run it after changing `config.js` news entries, `services_content.py` or the header and footer in `index.html`, and commit the result.

When the clinic gets its own domain, set `SITE_URL` at the top of `tools/build_services.py` (or run `SITE_URL=https://yourdomain.com python3 tools/build_services.py`) and run it again, so canonical links, previews and the sitemap use the new address.
